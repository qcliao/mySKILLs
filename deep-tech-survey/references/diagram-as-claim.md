# 示意图是可证伪的断言

核心主张:**图上每一个视觉属性都编码了一条断言。** 两块画成并排就是在说"它们能并发",
框画得宽一倍就是在说"它大一倍"。画图不是配插图,是**写一组会被逐条检查的声明**。

下面七条对任何示意图都适用 —— 时序图、内存占用图、架构通路图、统计图。

## 七条检查表

### 1. 并排 = 可并发 → 逐槽指出依赖为何允许

每一条并行边都要能回答"这两块之间为什么没有依赖"。

**典型失效**:时序图把同一批次的两个阶段画成并行,而后者的输入正是前者的输出 ——
依赖被违背。改法不是挪一下,而是**改成跨批次重叠**(第 t 批的后阶段 ∥ 第 t+1 批的前阶段),
因为后阶段依赖的是**上一槽已完成的**那份。

改完把逐槽的依赖论证**写进图下说明**,而不是只在脑子里验过。

### 2. 连续发射 = 资源无限 → 拿容量倒算槽位

**一张画对的流水图必须有 stall。** 没有 stall 的流水图几乎一定假设了无限 buffer。

**典型失效**:把搬运行画成一连串连发,被问"是不是没考虑空间限制,这里是直接一串做完了"。
核实后:槽位数是拿容量倒算的(约 3 个),每笔搬运前都有 acquire、槽位没腾出来就阻塞。
改完图上多了一条显式的 `等slot·buffer满` 红条,并标出三处 release 的源码行号。

做法:**先算容量能放几个槽位 → 再排时序 → 槽位耗尽处画 stall → 标出释放点。**

### 3. 尺寸 = 数量级 → 定死比例尺,用脚本复算

同一张图内比例尺必须固定(如 1KB = 1.5625px)。**所有矩形宽度用脚本验算,不目测。**

```python
SCALE = 800.0 / 512          # px per KB —— 一张图一个常量,写在最上面
def w(kb): return kb * SCALE  # 每个矩形宽度都走这个函数,不手写数字
```

比例尺不同的两张图**不能并排比较**,除非在图上标出各自的尺。若必须换尺
(小容量图放不下文字),在图注里写明"本图比例尺与图 N 不同"。

比例尺的用法之一是让约束**看得见**:把一个装不进容器的量按同一比例尺画得比容器框更宽,
超出部分用红虚线标出 —— 比在文字里写"它超了"有力得多。这类"溢出条"往往能同时
解释好几件事(为什么旧方案需要某个变换、为什么新方案不需要),值得提为全节论点。

**同类量必须同色。** 颜色也是一条断言:同一种东西在两张图里换了颜色,读者会以为
是两种东西。建议一开始就定一张小色表(输入/中间量/输出/溢出各一色)并全篇复用。

### 4. 嵌套层级 = 谁属于谁 → 区分"这一级"与"切进下一级的粒度"

这是最高频的错误类型(见 SKILL.md 自查表第 1 条)。同一个维度上往往有多个常量:
这一级的实际大小、切进下一级的粒度、最内层的计算块。**三者数值不同,别混用。**

相关的一条:**要区分"为了并行而切"和"为了搬运而切"** —— 归约维通常不参与并行切分
(切了要跨核合并),它上面的分段纯粹是搬运粒度。图上标签写错这一点,懂的人一眼看出来。

### 5. 柱高/坐标 = 统计值 → 由脚本从原始数据现算

统计图**绝不手写柱高**。一旦手绘坐标,正文数字更新时图不会跟着变 ——
这是最容易埋错、且最难发现的地方。

### 6. 线的位置 = 边界语义 → "超过"还是"达到"

阈值线画在格中间还是格线上,取决于语义。"**超过** 20 才如何"→ 线画在 20.5,
这样才准确表达"20 在线内、21 在线外"。

### 7. 图能渲染 ≠ 布局成立 → 算完坐标必须真渲染出来看

**一条硬规矩:SVG 不能只算坐标,必须真的渲染出来看。**

典型失效:初版有三处文字被分隔虚线穿过、窄框塞不下标签。全靠渲染后肉眼比对发现。
三招修法:放大比例尺、窄块改用**下方引线标注**、分隔虚线**下移到文字下方**。

窄块的判据:框宽不足以容纳标签时(如 20 多 px),不要硬塞,改引线。

## 该不该配图

**判据:图能替掉文字,而不是"这段该配个图"。**

价值在逐字原文的段落(条款原文、API 签名、精确措辞)**不要配图** ——
画成框反而丢信息。

## mermaid 还是手写 SVG

| 用 mermaid | 用手写 SVG |
|---|---|
| 纯拓扑:几个框一条链、流程分支 | 需要**精确空间语义** |
| 好改、不用算坐标 | 框高=容量、虚线框=生命周期、左右两栏同比例对照 |

判据一句话:**图里的尺寸和位置是否承载信息?** 承载就必须手写坐标,
因为 mermaid 的布局是它自己定的,你控制不了比例。

## 图与代码同放

时序图/流程图要**紧贴对应代码**放,而不是集中到一节。读者看图时就能对着代码验,
不用来回翻。集中的那一节只留跨方案的对比图,细节指回各自小节。

图上的阶段编号要与代码块的分隔注释、以及正文的阶段表**共用一套编号**,
三者互相锚定(见 `document-skeleton.md`)。

## 标签放不下时的三招

窄块塞不下文字是最常见的排版失败。按优先级:

1. **放大比例尺** —— 若整图还有富余空间,先调尺
2. **改下方引线标注** —— 窄块留空,标签放在图外用引线指过来
3. **缩写 + 图注解释** —— 最后手段,缩写必须在图注里展开

**分隔线不要穿过文字**:双缓冲/分区虚线若与标签重叠,把线下移到文字下方,
而不是把文字挪走(文字位置通常有语义)。

## 图注写什么

图注(caption)与读法(见 `document-skeleton.md`)是两件事:

- **图注**:这张图是什么、数据来自哪(源码文件、论文图号)、比例尺、
  "示意非精确"这类免责说明
- **读法**:从图里能得出什么结论

图注给**可核查性**,读法给**论点**。两者都不能省,但不要混在一句里。

## 数据来源要标在图上或图注里

图是二手表达,读者无法从图本身验证。所以:

- 复用论文原图 → 标明论文与图号,并给链接
- 自己画的时序图 → 标明折算依据("按 A=512 cycle / B=1024 cycle 折算")
  和源码出处(文件 + 行号)
- 统计图 → 标明数据文件与统计口径

**没有出处的图,读者只能选择信或不信** —— 而这正是可辩护性要避免的状态。
