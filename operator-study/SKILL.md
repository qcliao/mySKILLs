# 研究一个算子:从计算流到仿真流水图

目标不是"读过源码",是**能画出这个 kernel 的执行时序并说清每一步的精度**。
达到这个程度,瓶颈、设计动机、与另一套实现的差异都会自己浮出来。

## 五步流程

顺序不能换:③ 之前不动代码块,④ 之前不画流水图。

```
① 论文/文档 → 计算流       算什么、拆成哪几步、什么依赖什么
② 源码 → 真实计算流         调用链、grid、tiling、stage 边界
③ 关键代码片段 + 逐段对应   每段代码挂回 ① 的哪一步公式
④ 标清精度                  每段的输入/累加/输出 dtype,以及哪段没有自由度
⑤ 仿真流水图                按执行单元分行的时序图,含 stall
```

**每一步的产出都要落地成材料里的一个部件**:① 是公式/阶段表,② 是流程图,
③ 是代码块,④ 是代码里的精度旁注,⑤ 是时序图。

## 请求很短,交付不缩水

真实请求通常只有一句:"帮我分析一下 XXX 算子"。**这句话要的就是完整的五步产出。**
用户不说"画流水图""标精度",是因为那是默认交付物,不是因为不要 ——
要是每次都得他列一遍清单,这个 skill 就白写了。所以:**请求的长度不是交付的尺度**,
一句话的请求和一段详细需求,产出应该是同一份东西。

请求里没交代的,按下面补齐,并在开头一句话说明:

**先定口径。** 算子通常有一堆分支(causal / 2CTA / varlen / FP8 / paged / 不同 hdim)。
挑一条主路径,开头写明"本文口径:BF16 / hdim=128 / 非 causal / fwd",
并给出它确实是默认路径的证据(哪一行的判定)。**不定口径,后面所有数字都在分支间飘**,
读者对不上自己看的那份代码。其余分支留到末尾点名。

**默认只做前向。** 反向另开一篇,除非请求点名或前向已经交付完。

**每个数字带出处。** 常量、shape、精度档位、行为断言 —— 一律写成 `chunk_fwd.py:257`
这种可点击形式。没有出处的数字读者无法核,等于没写;而这份材料的读者
往往比你更熟这块代码。

**结尾必须有"未覆盖"一节**,区分"我没讲"和"我不知道":读过但没展开的分支列名,
没读的直接说没读。这一节决定读者敢不敢用这份材料 —— 边界不清的材料,
读者只能整份不信。

## ① 论文 → 计算流

拿到的应该是**一组公式 + 一张依赖图**,不是文字描述。三件事必须搞清:

- **拆成哪几个阶段**,每阶段算什么
- **哪个阶段是串行的** —— 通常只有一个,它决定了整个 kernel 的形态
- **每阶段的并行维度**(batch / head / 序列块 / 输出通道)

产出一张阶段表:`阶段 | 算什么 | 并行度 | 依赖谁`。**这张表是后面四步的锚**。

论文只给骨架与权威出处(章节号、图号),实现细节一律以源码为准。

## ② 源码 → 真实计算流

**先摸调用链,再看单个 kernel。** 顺序反了会陷在某个 kernel 的细节里,
看不出整体划分。

要回答的问题,按重要性排:

1. **几个 kernel / 几个 stage?边界在哪?** 边界处中间量必须落地(HBM / GM
   workspace),这是最贵的设计决策
2. **每个 kernel 的 grid 是什么?** 直接对应 ① 表里的并行度。
   `grid (⌈V/BV⌉, NT, B·HV)` 这一行比任何文字描述都准
3. **哪个维度在 grid 里,哪个在 kernel 内的 for 里?** 在 for 里的就是串行的
4. **tiling:每级切多大?为什么是这个数?** 反推它(见下)
5. **中间量放哪?** 寄存器 / 共享内存(SMEM/UB)/ 全局内存。这决定了能不能融合

**验证调用链要看实测,不要看文档。** 函数名随版本漂移;以当前代码里的
forward 编排为准,并注明"实测调用链"。

**注意函数的真实调用位置。** 踩过的坑:把一个只在 backward 调的函数画进了前向流程。
grep 它的所有调用点,不要看名字猜。

## ③ 关键代码片段 + 逐段对应

**贴的是执行流,不是源码。** 把与本条流程无关的分支、断言、日志删掉,只留能读通的
主干;开头交代文件路径与函数名,并注明这是"实测调用链"还是"结构示意"。

**用分隔注释把阶段切开**,编号与 ① 的阶段表一致,三级层次
`═══ 阶段 ═══` → `── 步骤 ──` → 行内注释:

```python
# ═══ ① fla/ops/utils/cumsum.py —— 门累积,log 域 ═══
# grid (NT, B·H):每个 program 管一个 chunk 的一个 head
    # ── Step 1:算 10 个 [16,16] 块,沿 K 方向 for 累加 ──
    b_g = tl.cumsum(b_g, axis=0)   # ↑ 这就是 ① 的第 2 步
```

**三类旁注,各有固定标记:**

| 标记 | 用途 | 例 |
|---|---|---|
| `# grid (...)` | 并行维度 —— 读者第一个问题永远是"什么在并行" | `grid (⌈V/BV⌉, NT, B·HV)` |
| `#@prec` | 这一步的数值精度(机制见 ④) | `#@prec BF16 输入 / FP32 累加` |
| `# ⚠` | 反直觉、易误读处 | `⚠ 相邻两发一个禁了 TF32、一个没禁,实际精度完全一样` |

`⚠` 专门标"你可能以为 X,其实是 Y"。**这类旁注价值最高,因为它拦住的是读者
将要犯的错**。上例的原因是输入已经是 BF16,那个开关被静默忽略。

**回指公式。** `# ↑ 这就是那条恒等式:log 域算差再 exp2,永不显式构造 1/γ`
—— 一行注释把代码和 ① 缝上。

## ④ 标清精度

**逐段标三个 dtype**:输入(喂给矩阵乘的)、累加(accumulator)、输出/落地。

```
kkt_solve:   输入 BF16 · 累加 FP32 · 输出 FP32(留在寄存器)
state 递推:  状态全程 FP32 寄存器累加,只在喂 GEMM 前降 BF16
```

**核心判据:这个量会不会被反复乘进自己?**
会 → 必须保高精度(串行回代链、状态递推、指数累积);不会 → 可以降。

四条必查:

- **主干 GEMM 一律低精度**(AI 芯片上高精度矩阵乘吞吐极差),所以"哪里保了高精度"
  才是信息 —— 那里就是精度敏感路径
- **配置可能被静默忽略**:`allow_tf32=False` 在输入已是 BF16 时完全无效。
  写下"这里关了 TF32"之前先确认它生效
- **等价性是数学的,差异是精度的**:数学上等价的两种形式,在低精度下误差
  同等大小 —— 别把"低精度的既定损失"当成某种形式引入的 bug。
  **验证基线必须同精度**
- **溢出不是精度档位能解决的**:若几个档位指数位宽相同,换档无用。
  解法是让危险量只以**比值**形式出现,并确认存在配对源 + 次序保证

**精度标注别写成普通注释** —— 会淹在代码里。约定一个前缀 `#@prec`,生成 HTML 时
整行套高亮样式(琥珀底 + 深橙字 + 左侧橙条),让它成为灰底代码块里**唯一的暖色**,
扫一眼就能找到所有精度切换点。转换端匹配
`^(\s*[│|]?\s*)(?:#|//)@prec\s*(.*)$`,保留前置缩进与 `│` 这类树形符号,
`#` 和 `//` 两种注释符都支持。

## ⑤ 仿真流水图

**这是整个流程的收口。画不出来,说明 ②③ 还没搞清。**

用 mermaid gantt,`section` = **执行单元**(不是逻辑步骤):

```
gantt
    title FA4 · Qh/Ql 两个 Q 子块 ping-pong(C1=Q@Kᵀ,C2=P@V;Load 受 kv_stage=3 门控)
    dateFormat X
    axisFormat %s
    section Load w14 TMA
    K0 slot0 :0, 2
    V0 slot1 :4, 6
    等slot·buffer满 :crit, 10, 16
    K2 slot1 :16, 18
    section MMA w12 TensorCore
    C1 Qh@K0 :4, 6
    C2 Ph0@V0 :10, 12
    section Softmax0 w0-3 = Qh
    sm Qh b0 :6, 10
```

六条约定:

**a. section = 物理执行单元。** GPU 上是 warp 组 / TMA / TensorCore;
NPU 上是 Cube / Vector / MTE2 / MTE3 / FixP。**按逻辑步骤分行是错的** ——
流水的本质是不同单元同时干活。

**b. `dateFormat X` + 整数槽位。** 不追求 cycle 精确,标题里写清折算依据
(如"按 GEMM=512 cycle / softmax=1024 cycle 折算,示意非 cycle 精确")。

**c. 每块标清是什么。** 不写 `GEMM`,写 `C1 Qh@K0` —— 哪一发、算的是哪两个矩阵。
搬运块标 **slot 号**,体现环形复用。

**d. 必须有 stall。** 用 `:crit,` 画阻塞条。**没有 stall 的流水图几乎一定假设了
无限 buffer** —— 这是最常见的错。先算容量能放几个 slot,再排时序,
槽位耗尽处画 stall,并标出释放点的源码行号。

**e. 每条并行边都要能论证。** 图下写"逐槽看"说明:
`C2 t0`[2-3] 与 `V1 t1`[2-3] 并行 —— `C2 t0` 依赖的是上一槽已完成的 `V1 t0`,
不是同槽的。**同一批次的两个阶段有依赖时不能画成并行。**

**f. 图下给读图要点。** 编号列出:哪两行是独立的、每发标的是什么、
buffer 有几个 slot、哪段是阻塞。

## 反推:tiling 常量从哪来

材料里的"神秘常量"几乎都能反解出来,**把陈述变成推导比多给一个数字有用**:

```
容量约束 ≥ 各驻留量之和  →  解出块大小上界
例:3 × 576 × s2Base × 2B + 72KB ≤ 512KB  ⟹  s2Base ≤ 130  ⟹  取 128
例:一个 K slot 与一个 V slot 各 128×128×2B = 32KB,Q+O 吃掉约 128KB
    余下容量 ⟹ kv_stage ≈ 3
```

反推也顺带暴露量级错误:算不出来的数,往往是某处单位或层级搞错了。

**区分三类切分,别混用**(最高频的错误):
- **为并行而切**(分核/分 block):归约维通常**不切**,切了要跨核合并
- **为装进下一级存储而切**:这一级的实际大小 ≠ 切进下一级的粒度,数值常差几倍
- **为搬运而切**:纯粹是 DMA 粒度

## 横向对比多套实现

**分歧处 = 设计自由度,一致处 = 硬约束。** 对比 N 套实现时:

1. **先立统一视角**:明确"它们计算内容完全相同,不同的只有 A 和 B 两件事"
   —— 否则读者以为处处都不一样
2. **显式列出差异轴**,不要让读者自己归纳。典型三轴:
   **stage 边界划在哪** / **每步的实现选择** / **中间量放哪**
3. **对比表按不变量排行**(阶段、公式项),不按各家变量名排 —— 命名根本对不上
4. 找**天然对照点**:同一件事各家选了不同参数(如块内三角求逆的分块粒度
   16 / 16→32→64 / 32),这类分歧最能说明"按硬件选"

常见的真实分界点,值得专门找:
- **要不要把每个中间状态落地** —— 换来并行度,代价是 O(N) 显存
- **融合到什么程度** —— 少一个 kernel 就少一次中间量往返
- **归一化/门控在哪一步施加** —— 提前施加可能破坏某个可复用结构
