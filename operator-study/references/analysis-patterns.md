# 复现的分析套路

这些是在多个算子上反复用上的分析手法,不绑定具体 kernel。

## cost model:先算账,再看 profile

对单个 tile 逐条流算 cycle,**比例最大的那条就是瓶颈**;单 tile 的比例
≈ 整个算子的 MFU(因为算子就是同一种 tile 重复)。

粗略公式(按硬件替换常数):

```
矩阵乘   ≈ M·K·N / 单周期吞吐
搬运     ≈ 字节数 / 带宽
写回     ≈ 输出元素数 / 每周期写出量   (还受 bank 冲突 / 双目标约束)
向量     ≈ 元素数 / 每周期处理量 × 指令条数
```

**用途不是算准,是定方向:**
- 矩阵乘最大 → compute-bound;某条搬运最大 → memory-bound
- 估算给**理论下界**,profiler 给**真相**。对不上通常是模型漏了项
  (bank 冲突、scalar bound、同步开销)——**去补模型,不是改结论**

**瓶颈分两类,处理方式完全不同:**
- **可调** —— 换指令 / 重调分块比例就能压下去,留在当前迭代里解决
- **结构性** —— 无论怎么 tiling 都盖不住,因为它是**计算流本身**带来的
  (某个中间量反复在片上片外往返)。这类只能改计算流(见下"动手术")

## 单 tile 内的流水,与 tile 间的流水正交

两级流水,别混:

- **tile 内**:同一个 tile 的 `搬入 → 计算 → 搬出` 落在不同 pipe 上。
  串行则耗时从 `max` 退化成 `sum`;双缓冲(乒乓)解开依赖
- **tile 间**:相邻 tile / stage 重叠,靠预取进入稳态

**tile 间排满了,单 tile 内部仍可能跑不到峰值。** 这类"单 tile 峰值"问题:

- **issue queue 阻塞** —— 发射队列满或依赖未清,下游 pipe 断流
- **IPC 打不满** —— 在飞的独立指令太少;循环开销/地址计算占比过高
- **scalar bound** —— 地址计算、循环控制、同步标志都是标量指令,喂不动算力单元
- **bank 冲突** —— 共享存储/寄存器文件的 bank 冲突把并行访存串行化
- **寄存器压力** —— 活跃中间量太多 → spill / occupancy 掉档
- **依赖 stall** —— RAW/WAR/WAW、等长延迟 load 的结果

**双缓冲会逼小 tile**(容量要分两份),所以 tile 间流水会反馈回 tiling 选择。
这是个闭环,不是单向流程。

## 融合的判据:少一次中间量往返

融合的收益来源是**少一次中间量落地**,不是"少一次 kernel launch"。
所以判据是:**这两步之间的中间量有多大、往返多少次。**

反过来,拆开的收益是**并行度**:某一步的并行维度比另一步高时,
拆开能让高并行的那步跑满。代价是中间量必须落地。

**典型的真实分界**:要不要把每个块的中间状态都落地。落 → 后续步骤恢复完整并行,
代价是 O(块数) 显存;不落 → 省显存,但后续步骤只能跟着串行段走。
**算一下那个显存是多少 MB**,这个数就是权衡的价码。

## 串行链:找到它,然后想办法缩短或切开

多数 tiled kernel 里**只有一个阶段是串行的**。找到它之后三条路:

1. **缩短链长** —— 把逐元素递推改写成逐块递推,链长从 `L` 降到 `L/C`。
   代价是块内多算一批 `C×C` 的量:**用矩阵运算换掉长串行**,
   在有矩阵单元的硬件上稳赚
2. **前置无关计算** —— 串行段里不是每一步都依赖前一步的结果。
   **判据:这个量的表达式里含不含那个被递推的状态?** 不含就能提到串行段之前算完
3. **切开** —— 把序列切成若干段,段间用某种可结合的变换拼回来
   (需要该运算满足结合律或有仿射形式)

## 数学动手术:四步

当常规调优盖不住结构性瓶颈时:

```
① 定位     哪个中间量在反复往返 / 哪条指令必须用昂贵单元
② 找等价   数学上等价、但避开那个昂贵操作的形式
③ 补数值   等价变换往往牺牲数值范围/精度,补稳定化手段
④ 卡边界   明确这个变换在什么输入范围内成立,超出怎么办
```

两个真实例子的形状(不是细节):
- 把浮点缩放换成**对指数位的整数加**(利用 IEEE-754 的位布局),
  于是那步能在便宜的单元上做、甚至能用原子加在全局内存上原地完成
- 把高精度激活**分解成两个低精度矩阵乘**,消掉中间的反量化往返

共性:**四步法是在既定计算流内调度,动手术是直接改计算流本身。**
改完要回到 ① 重新走一遍分块与 cost model。

## 数值范围:配对与因果性

指数累积类的量(前缀积、累积衰减)会溢出。**解法不是换精度档位**
—— 若几个档位指数位宽相同,换档无用。

**解法是让危险量只以比值出现**,并检查两个前提:
1. **存在配对源** —— 每处出现的地方都能找到一个同类量与它相除
2. **有次序保证** —— 配对后的比值必须 ≤ 1(通常来自因果性/下三角结构)

缺一个就会溢出。实现上一律**在 log 域算差再取指数**,不先算出该量再做除法。

## 门控 / 缩放能不能写成 mask

一个反复出现的分水岭:某个逐元素的缩放因子,**能不能提到求和号外面变成一个
与数据无关的 mask**。

**判据:换一组数据、保持缩放因子不变,所需的 mask 变不变?**
- 不变(mask 与数据无关)→ 可以用原始数据做矩阵乘,再逐元素乘 mask。
  被缩放的量**从不显式构造**
- 变(缩放因子钻进了求和号,与数据分量纠缠)→ 必须真的先算出缩放后的量再做矩阵乘

后者会把"缩放因子的倒数"逼到显式出现,于是引出上面那个数值范围问题。
**这条判据决定了两套实现能不能共用同一套 kernel 结构。**

## 精度自由度在哪

**主干矩阵乘一律低精度**(高精度矩阵乘吞吐极差),所以看点是"**哪里保了高精度**"。

**判据:这个量会不会被反复乘进自己?**
- 会 → 串行回代链、状态递推、指数累积:必须保高精度
- 不会 → 一次性的矩阵乘:可以降

**分阶段的一个附带好处就是各段可用不同精度** —— 这也是为什么精度表总是按 stage 排。

## 分核:掉并行度的总是串行那段

各段的并行度不同:并行段是 `块 × head × batch`,串行段只有 `head × batch`。
差一个量级 —— **所以核用不满的地方几乎总是串行段**。

看实现怎么处理这个:是接受它(串行段少用几个核),还是把串行段也切开
(见上"切开")。
